# PROJECT_NOTES — Trenio, клиентский кабинет

## 1. Что это за проект

Мобильный веб-прототип **клиентского кабинета** сервиса персонального тренера Вадима
(бренд **Trenio**): план тренировок по циклам и дневник их выполнения, дневник питания
с нормами КБЖУ, отчёты с замерами тела и профиль с пакетами подписки.

- Статический сайт: HTML + CSS + ванильный JS, **без сборки, без npm, без ES-модулей**.
- **Бэкенда нет.** Все данные — демонстрационные, живут в `js/data.js`, состояние — в памяти
  страницы. Перезагрузка возвращает исходное состояние, кроме темы и профиля (только они
  лежат в `localStorage`).
- Задача прототипа — согласовать дизайн и UX с тренером, а не работать с реальными клиентами.
- Открывается двойным щелчком по `index.html` (`file://`) и на статическом хостинге
  (GitHub Pages). Отсюда ограничения: нулевые внешние запросы, только относительные пути.
- Экраны: `#/home` (Главная), `#/workouts` (Тренировки), `#/nutrition` (Питание),
  `#/reports` (Отчёты), `#/profile` (Профиль). Профиль открывается из карточки клиента
  в сайдбаре и с главной, в нижнем таб-баре его нет. Старый адрес `#/supplements` живёт
  только как редирект на `#/nutrition` — отдельного экрана добавок больше нет.
- У «Тренировок» две вкладки — «Текущий цикл» и «Архив». Вкладка хранится в `STATE`,
  а не в адресе: маршрут остаётся один — `#/workouts`.
- Есть нижние шторки (bottom sheet) для контактов, установки на экран и справок,
  тосты, «док» завершения тренировки и зачатки PWA (`beforeinstallprompt`, `appinstalled`).

`data` → `util` → `state` → `ui` → `views/*` → `app`.

## 3. Соглашения

- **Один глобальный неймспейс.** Каждый файл — IIFE вида
  `(function (App) { ... })(window.App = window.App || {});` и дописывает свой раздел:
  `App.data`, `App.util`, `App.state`, `App.cycle`, `App.measurements`, `App.ui`,
  `App.views.<route>`, `App.const`. Никаких модулей, экспортов, бандлера и npm.
- **Никаких внешних запросов.** Без CDN, веб-шрифтов, внешних картинок, аналитики.
  Шрифт — системный стек (`var(--font)`), иконки — инлайновый спрайт `<symbol>`/`<use>`
  (`App.util.icon("name")` → `<svg class="icon"><use href="#i-name">`).
- **Языки.** Весь видимый текст — русский (`<html lang="ru">`), код, комментарии
  и идентификаторы — английские. Форматирование чисел — через `util`
  (`weight()` 86,4 · `num()` 2 100 · `plural()` дн./дня/дней).
- **Разметка через строки.** View-функция возвращает HTML-строку; данные в текст
  подставляются только через `escapeHtml()`.
- **Стили — на токенах.** Цвета/отступы/радиусы берутся из `css/tokens.css`
  (`var(--surface)`, `var(--accent)`, `var(--radius)` …). Новая тема не нужна:
  переключение `html[data-theme="dark"|"light"]`. Тема и профиль (телефон, email, аватар)
  хранятся в `localStorage` — ключи `vadim-theme` и `trenio-profile`; тема применяется
  ещё в `<head>` до первой отрисовки, этот инлайн-скрипт трогать нельзя, иначе появится
  вспышка светлой темы.
- **Поведение — на data-атрибутах.** `data-nav` (навигация и `aria-current`),
  `data-action` (делегированный клик), `data-form="measure"` (сабмит),
  `data-focus`/`data-focus-key` (куда вернуть фокус после перерисовки),
  `data-day`/`data-index`/`data-key`/`data-cycle` (параметры действия),
  `data-demo="true"` (временные демо-блоки, которые потом удаляются). Обработчик один —
  `handleAction()` в `js/app.js`.
- **Доступность.** После смены экрана фокус уходит на `h1` с `tabindex="-1"`;
  ссылки навигации получают `aria-current="page"`; тач-цели ≥ 44px; видимые
  фокус-кольца; `prefers-reduced-motion` уважается; тост — `role="status"`.
- **Без прямого DOM.** Обработчик не правит разметку точечно: он меняет `STATE`
  и вызывает `render(...)`. Точечные исключения — сворачивание справки по полю,
  «док» тренировки (`syncDock` пишет только свой слот) и шторка (`openSheet`/`closeSheet`).

## 4. Поток данных

```
js/data.js  (App.data, неизменяемые демо-данные)
      │
      ├─ js/state.js  buildState()  ──►  App.state (мутабельное состояние сессии)
      │        считается один раз при загрузке из DATA + текущей даты/времени;
      │        рядом App.measurements (замеры) и App.cycle (селекторы по DATA.cycles + STATE.cycle)
      ▼
js/views/<route>.js   view()  ──►  HTML-строка
      │
      ▼
js/app.js  render(route, options)
      • innerHTML в #screen-<route>, остальные .screen скрываются
      • анимация колец (если не options.static)
      • document.title из PAGE_TITLES, body[data-route]
      • syncNavigation() / syncClientMeta() / syncDock()
      • scrollTo(0,0) при смене экрана или options.scrollTop, иначе возврат сохранённой позиции
      • возврат фокуса (heading | focusSelector | focusKey) с preventScroll: true
      ▼
пользователь жмёт [data-action]
      ▼
делегированный click → handleAction(action, trigger, event)
      • читает trigger.dataset, проверяет границы
      • мутирует App.state (или вызывает App.measurements.save)
      • render(route, { static: true, focusKey })
```

Ключевые детали:

- Роутинг — hash. `resolveRoute()`: пусто → `#/home`, старый `#/supplements` →
  `#/nutrition`, неизвестное → `#/home` (через `history.replaceState`, чтобы назад
  не возвращало на битый адрес). `hashchange` → `onRouteChange()` → `render()`.
- `render()` перерисовывает **весь экран**. `options.static: true` — не перезапускать
  анимацию колец (чтобы прогресс не «прыгал» после каждого клика).
- Сохранность между перерисовками обеспечивают только `STATE` и `data-focus`-ключи;
  позиция скролла сохраняется при обновлении «на месте» (тот же маршрут), а при смене
  экрана и при `scrollTop: true` страница уходит наверх. Повторный клик по пункту
  меню текущего экрана — не просто «наверх»: `go()` заново собирает опции рендера.
  Для «Тренировок» он дополнительно возвращает вкладку «Текущий цикл», выбирает
  следующую невыполненную сессию и прокручивает страницу наверх.
- Персистентность: тема (`localStorage["vadim-theme"]`) и профиль
  (`localStorage["trenio-profile"]` — `phone`, `email`, `avatar` в виде data URL).
  Замеры, отметки тренировок, вода и блюда живут в памяти до перезагрузки.
- Побочные ограничения: экран рендерится целиком, поэтому обработчики вешаются
  не на элементы, а на `document` (клик/change/input/submit).

## 5. Где живут демо-данные

Единственный источник — **`js/data.js`**, объект `App.data`. Всё остальное читает его
только на чтение.

| Ключ | Что внутри |
| --- | --- |
| `client` | имя, возраст, рост, цель, телефон, email |
| `coach` | имя, телефон, ссылка и ник в Telegram |
| `targets` | нормы: `kcal`, `protein`, `fat`, `carbs`, `water` (стаканы) |
| `goal` | цель по весу: старт / текущий / целевой + история веса |
| `message` | сообщение тренера на главной |
| `nutritionAdvice`, `nutritionTips` | текстовая норма и советы |
| `mealTimes` | 5 приёмов пищи с временем |
| `menus` | 7 дней × приёмы пищи × блюда; блюдо — `D(name, kcal, protein, fat, carbs)`, ккал считаются из БЖУ |
| `cycles` | `{ current, archive }`; цикл — 12 сессий по шаблонам A–D (см. ниже) |
| `supplementsInfo` | добавки + дисклеймер (блок добавок показывает Питание) |
| `subscription` | пакеты: `training {status, sessions, cycleNumber}` и `nutrition {status, days, activatedDaysAgo}` |
| `generalRecs` | вводная заметка и общие рекомендации по тренировкам |
| `tableLegend` | легенда таблицы подходов (что значат колонки) |
| `restHint` | подсказка про отдых между тренировками |
| `measurementFields` | 9 полей замеров: `key/label/unit/group/min/max/howTo` |
| `measurementsSeed` | 8 недельных замеров (последний — 7 дней назад), копируются в `STATE` |

Правила:

- Даты в данных относительные: `isoDate(shiftDays(n))`, чтобы прототип всегда
  выглядел «свежим». Хардкодить конкретные даты в данных или во вьюхах нельзя.
- Блюдо описывается БЖУ, калории не пишутся руками (`D()` считает `k = p*4 + f*9 + c*4`).
- Тренировка — шаблон из `cycleTemplates`: `{ key: "A", title, muscles, minutes, blocks }`;
  блок — `{ type: "cardio" | "warmup" | "main", title, items }`; упражнение —
  `{ name, sets: "4 × 12", weight: "40 кг", tempo, rest, note? }`. Для упражнений
  на время `sets: "3 × 40 сек"`, `weight: "свой вес"`.
- Тексты, которые видит клиент, лежат в данных, а не в вёрстке. Меняя контент,
  правьте `data.js`, а не view.
- Словарь маршрутов тоже здесь: `App.const = { DAY_SHORT, ROUTES, PAGE_TITLES, SCREEN_IDS }`.
  Новый экран без правки этих трёх словарей не заработает.
- Код сборки цикла (`cycleTemplates`, `buildCycle()`) тоже лежит в `data.js`, но наружу
  отдаётся только готовый `DATA.cycles` — вьюхи и `App.cycle` про шаблоны не знают.

### Модель цикла

Цикл — это 12 тренировок, собранных `buildCycle()` из четырёх шаблонов A–D, которые
повторяются по кругу. У цикла есть `id`, `number`, `startedAt`, `finishedAt`, `sessions`;
у сессии — `number`, `date`, `doneDate`, `template`, `blocks`, а у упражнений — `id`
для отметок. `doneDate` заполнен только у выполненных сессий архива.

Текущий цикл живёт не в данных, а в состоянии: `STATE.cycle.done` — `{номер: iso-дата}`,
`STATE.cycle.itemDone` — `{id упражнения: true}`, `selected` и `tab` — что открыто.
Поэтому отметки сбрасываются перезагрузкой, а даты в карточке цикла считаются
от последней выполненной сессии (`App.cycle.lastDoneDate`), а не от «сегодня».

Пакет тренировок (`STATE.training.status`) бывает в трёх состояниях:

- `active` — идёт цикл: доступны карточки сессий, отметки упражнений и «док» завершения;
- `completed` — все 12 тренировок сделаны: цикл уходит во вкладку «Архив», вместо
  сессии — итоги, кнопка завершения скрыта;
- `none` — пакета нет: вместо плана пустое состояние с общими рекомендациями
  (`generalRecs`) и предложением написать тренеру.

Завершение 12-й сессии само ставит `completed` и переключает на «Архив»; отмена
отметки возвращает `active`. Остальные переходы — только через демо-панель.

### Демо-панель

На «Профиле» есть карточка с `data-demo="true"` — переключатель статуса пакета
тренировок (`Активен` / `Цикл завершён` / `Не активирован`) и кнопка «Сбросить
демо-данные» (`data-action="reset-demo"`: удаляет `trenio-profile` и перезагружает
страницу). Это временный инструмент для показов, перед релизом карточка удаляется
целиком — её разметка лежит в `demoCard()` (`js/views/profile.js`), стили — `.demo-card`
в `css/profile.css`.

## 6. Как добавить экран

Пример — экран «Прогресс» с маршрутом `progress`.

1. **`js/data.js`** — расширить словари:
   - `ROUTES` → добавить `"progress"`;
   - `PAGE_TITLES.progress = "Прогресс — Trenio"`;
   - `SCREEN_IDS.progress = "screen-progress"`.
2. **`index.html`** — добавить пустую секцию внутрь `.page` (рядом с остальными,
   до `.app-footer`):
   ```html
   <section class="screen" id="screen-progress" data-screen="progress"
            aria-labelledby="progress-title" hidden></section>
   ```
   Файл-вьюху подключить `<script defer src="js/views/progress.js"></script>`
   **перед** `js/app.js`.
3. **Навигация** — ссылка в сайдбаре (`.side-nav`) и, если экран должен быть
   в нижнем таб-баре, в `.bottom-nav`; обязателен атрибут `data-nav="progress"`.
   В таб-баре помещаются 4 пункта — пятый экран обычно открывают ссылкой
   из другого экрана или из сайдбара.
4. **`js/views/progress.js`** — по образцу соседей:
   ```js
   (function (App) {
     "use strict";
     const DATA = App.data;
     const STATE = App.state;
     const { icon, escapeHtml } = App.util;
     App.views = App.views || {};

     function progressView() {
       return `<div class="screen-head">… <h1 id="progress-title" tabindex="-1">Прогресс</h1> …</div>`;
     }

     App.views.progress = { view: progressView };
   })(window.App = window.App || {});
   ```
   Заголовок `h1` обязан иметь `id` из `aria-labelledby` и `tabindex="-1"` —
   на него переводится фокус после перехода.
5. **Действия** — новый `case` в `handleAction()` (`js/app.js`): прочитать
   `trigger.dataset`, проверить границы, мутировать `STATE`, затем
   `render("progress", { static: true, focusKey: trigger.dataset.focus })`.
6. **Стили** — небольшие экраны пишутся в `css/screens.css`, крупные (как Тренировки
   и Профиль) выносятся в свой файл и подключаются `<link>` после `screens.css`.
   Всё на токенах, с проверкой 320px и обеих тем.
7. **Проверить** — `#/progress` открывается и переживает перезагрузку; `document.title`
   верный; `aria-current` на нужной ссылке; «Назад» в браузере работает; фокус
   после перехода на заголовке; внешних запросов не появилось. Если у экрана есть
   вкладки, повторный клик по его пункту меню должен возвращать на первую и наверх.

## 7. Проверки перед сдачей правки

- Открыть `index.html` с диска: консоль без ошибок, все 5 маршрутов живы, `#/supplements`
  редиректит на `#/nutrition` (это легаси-адрес, отдельного экрана больше нет).
- «Тренировки»: вкладки «Текущий цикл» / «Архив» переключаются; повторный клик по пункту
  меню возвращает на «Текущий цикл», выбирает следующую невыполненную сессию и крутит
  страницу наверх; отметки упражнений и «Завершить тренировку» не теряются после
  перерисовки; 12-я сессия уводит в «Архив» с тостом «Цикл завершён!», отмена отметки
  возвращает цикл в работу; демо-панель переключает все три состояния пакета.
- Обе темы, ширина 320px без горизонтального скролла (широкие таблицы скроллятся внутри себя).
- Числа согласованы между экранами: вес в «Главной», карточке цели, последнем замере
  в «Отчётах» и строке профиля — одно и то же значение.
- Персистентность: тема и телефон/email/аватар переживают перезагрузку, отметки и замеры — нет.
